================================================================================
KNOWN ISSUES  --  Dama (src/main/java/Dama.java)
================================================================================

The actionable issues below have been fixed; the remaining items are conscious
design choices or a disproportionate rewrite for a local hot-seat game.  The app
compiles cleanly and has no known crashes or scoring errors.

--------------------------------------------------------------------------------
FIXED
--------------------------------------------------------------------------------

1. By Points leaderboard now filtered like By Moves.
   byPointsScores() now uses "where highestpoint > 0", so a brand-new player who
   has never scored no longer shows up with 0 / n/a -- matching byMovesScores().

3. Top-3 cap is now documented in the UI.
   The leaderboard titles read "Top 3 by Points" / "Top 3 by Moves", so the
   i<3 limit is stated rather than silent.

5. Draw-offer ✕ can no longer silently consume an offer.
   overlayConfirm() now disables the title-bar ✕ while a draw prompt is up, so the
   only way out is an explicit Yes/No.  "No" declines / backs out.

6. Blank board until a game actually starts.
   The Board now tracks boardVisible and paints pieces only once play has begun.
   After clicking New Game (before picking players) -- and after cancelling setup
   with ✕ before any game -- the board reads as empty instead of a full, dead
   position.  The final position still stays on screen after a game ends.

8. Low-contrast text lightened.
   The Serif message label and p1Score were brightened for better contrast on the
   dark-red (69,0,0) background.

9. Dead code removed from purge().
   The two commented-out clear() lines are gone.

--------------------------------------------------------------------------------
REMAINING (by design / out of scope)
--------------------------------------------------------------------------------

2. No automatic draw / stalemate detection.
   A game ends only by no-legal-move, Resign, or the Draw button.  There is no
   threefold-repetition, no-progress, or king-shuffle rule, so two kings can in
   principle move forever.  Acceptable for a hot-seat game; adding a full
   repetition/no-progress tracker is a disproportionate rewrite for this project.

4. Loser can still set a "highest point" record, and the opponentpoint /
   opponentmoves columns store the opponent's NAME (surfaced honestly via the
   "Opponent (Pts)" / "Opponent (Moves)" headers).  By design -- a conscious
   choice, not an oversight.

7. Can't abandon an in-progress game to start a fresh one except via Resign/Draw
   (New Game is disabled mid-game).  Minor; intentional.

10. JDBC runs on the EDT (databaseConnect + every query).  Fine for a local SQLite
    file, but technically blocking work on the UI thread.  Not worth the added
    complexity of a background worker for this app.
